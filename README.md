# カブぐらし — 2年間の投資家生活

Cloud Storageで配信できる、ビルド不要の静的ゲームです。公開対象は `site/`。ゲーム処理と保存はブラウザ内で完結します。

## 起動・検証

- `node scripts/serve.cjs`：http://127.0.0.1:8080 で起動。
- `node --test tests/engine.test.cjs`：ゲームルールと保存の回帰テスト。
- `node tests/browser.cjs`：PlaywrightによるPC・スマホ画面の操作テスト。`NODE_PATH`でPlaywright、`KABU_BROWSER`でChrome等の実行ファイル、`KABU_SCREENSHOTS`で画像出力先を指定できます。
- `node scripts/balance.cjs`：各職業200シードの試行プレイ。調査済み情報に基づく分散投資と、バイト・勉強・情報収集の組み合わせを評価します。人間のクリア率を予測するものではなく、調整を比較するためのサンプルです。

## 基本ルール

初期資金100万円、期間24か月。毎月最大2回の行動を選べます。株は行動の前・途中・後に100株単位で売買でき、行動数を消費しません。「月を締める」は行動や売買を省略して選べます。未使用の行動は翌月に繰り越しません。

半年ごとの期限目標は200万、500万、1,200万、3,000万円。イベントと配当を反映した月末総資産で判定します。未達成でも強制終了せず、24か月まで継続します。達成時のみ配当倍率＋0.10、毎月の調査pt＋2からひとつ選びます。24か月目も達成ボーナスを選べますが、プレイ期間は延長しません。

## 職業Lvと行動（v4）

すべてLv.0から、開始専用の職業ptを2ポイント振り分けます。1ptで好きな職業のLvを1上げ、開始前は「＋／−」で振り直せます。同じ職業をLv.2にする、2職業をLv.1にする、一部または全部のptを使わずに開始する形に対応します。初期画面の特徴説明には収入額・倍率・獲得量などの具体値を表示せず、Lvと残りptで振り分けを確認します。すべての職業が独立してLv.5まで育ちます。

| 職業 | 成長条件 | Lvによる効果 |
| --- | --- | --- |
| フリーター | バイト累計2 / 5 / 9 / 14 / 20回 | バイト14万円＋Lv×4万円 |
| 資産家 | 累計配当10 / 30 / 70 / 140 / 250万円 | 配当倍率1＋Lv×0.12（目標報酬は加算） |
| インフルエンサー | SNS投稿累計2 / 5 / 9 / 14 / 20回 | 発生確率＋10＋Lv×2ポイント、最大20ポイント |
| トレーダー | 勉強累計2 / 5 / 9 / 14 / 20回 | 情報収集で3＋Lv pt |

条件は開始後の累計値。最初の条件達成で振り分けた初期Lvから1上がり、以降も条件ごとに成長します。例えば初期Lv.1なら最初の条件でLv.2になります。未使用ptは開始後の育成には使わず、行動と配当で成長します。バイト・情報収集・勉強・SNS投稿は各1行動。情報収集は調査ptを獲得し、勉強はトレーダーの成長を進めます。

SNS投稿は対象イベントを選択し、未調査のイベントにも繰り返し投稿できます。補正は同じ段階の決着まで持続し、発生確率は95%で止まります。上限に届く投稿は残りのポイントだけ加算。上限到達済みのイベントは対象選択で「応援は最高潮」と表示します。成長前のLvで投稿効果を計算し、その後にLvアップします。

職業Lv欄は現在Lv・次のLv・条件・現在の達成量・残りを表示します。次Lvの効果は達成時のポップアップで条件とともに表示。交流・ENCOUNTERS・従来の実績報酬は職業成長へ置き換えました。

## イベントと調査

イベントは4枠、通常1〜3か月後に決着。「あと1か月」は今月末です。期日前は同じID・期限・調査状態を引き継ぎ、決着後に新しいイベントを補充します。同じ月に同じタグのイベントは決着しません。新規イベント・連続イベントの次段階が既存予定と重なる場合は、重ならない月まで期限を延ばします。旧セーブで既に重複している場合は、2件目以降を調査・SNS補正を維持して延期します。異なるタグが同じ銘柄に影響することはあります。

初期調査ptは3。1ptでタイトル・タグ、続いて2ptで成功時と失敗時の値動き、3ptで発生確率を開示します。調査は行動数を消費せず、ptは翌月へ持ち越します。未調査時はイベント番号と残り月数を表示し、投稿の加算量も確認できます。

企業とイベントのタグが1つでも一致すれば対象。複数タグが一致しても1イベントの値動きは1回分です。銘柄ごとの株価グラフには開始時から各月末の終値を表示し、点のツールチップと履歴で数値を確認できます。

### バランス

成功率が低いほど成功時の上昇幅と失敗時の下落幅が大きくなります。名前にも「堅実な改善」「大きな挑戦」などの規模感を追加しました。名前と値動きは基礎成功率を基準とし、SNS投稿では変わりません。

| 基本発生確率 | 成功時の上昇幅 | 失敗時の下落幅 |
| --- | --- | --- |
| 90% | +20% | -10% |
| 80% | +30% | -20% |
| 70% | +40% | -30〜-40% |
| 60% | +55% | -55% |
| 50% | +70% | -80% |
| 40% | +80% | -85% |
| 20% | +100% | -95% |

株価を負にしないため、下落幅は最大95%とします。新規抽選の相対重みは70%以上が全期間6、70%未満が1〜6月に0.25、7〜12月に1、13〜18月に3、19〜24月に5です。開始時の単発・連続イベント各1枠は維持します。連続イベントは後の段階ほど成功率が下がります。

## 連続イベント・決算

連続イベントは通常の4枠に登場。タグ調査で現在の段階数が分かります。標準データには6種類の3段階計画があり、期間は1 / 2 / 2か月です。

次の段階は新しいIDで追加。タグの調査状態を引き継ぎ、値動きと発生確率を再調査します。前段階の成功で見込み＋10ポイント、失敗で−10ポイント、累積補正は±25以内。基礎確率とこの補正を20〜95%に収めてからSNS補正を加算し、最終上限95%を適用します。SNS補正は段階ごとにリセットします。

最終成功で対象株の月次配当利回り＋1ポイント（上限20%）。段階決着時に2回以上対象株を保有し、最終判定にも保有していれば、対象保有時価の4%を追加獲得します。

決算は「期日のイベント → 配当 → 職業成長 → 目標判定 → 新しい月」の順。配当はイベント後の株価と成長前の配当倍率で計算し、資産家Lvアップ後の倍率は次の配当から適用します。

## 保存・公開

v4の保存キーは `kabugurashi-careers-v4:` とURLパスの組み合わせ。旧版は別キーに保管し、職業Lv版は新しい挑戦から始まります。全職業Lv、行動回数、配当、イベント、調査状態、SNS補正、乱数、履歴を保存します。行動を省略した月やゲーム終了時も復元できます。旧ルールで目標未達により途中終了した保存は、翌月から再開します。

v4内でのイベント確率・値動き・文面・タグの調整は保存を継続できます。銘柄順・段階の期間などの構造変更は互換性を検証します。結果は演出前に確定・保存し、演出スキップでも成長条件と効果をまとめて表示します。

公開は既存のGitHub Actionsから `site/` をCloud Storageへ同期します。
